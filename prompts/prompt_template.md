# Claude 프롬프트 템플릿 (v6)

이 파일은 청크 변환 시 사용할 프롬프트 템플릿입니다.
각 `{...}` 부분은 실행 시 동적으로 치환됩니다.

---

## 템플릿

```
다음 법학 문제 텍스트를 JSON으로 변환해주세요.

### 구조 정보

- **문제 범위**: {question_range}
- **선지 기호**: {option_symbols}
- **문제당 선지 수**: {options_per_question}
- **해설 구분자**: {explanation_marker}

### 텍스트 상태

- **깨진 문자 비율**: {broken_char_ratio}%
- **과도한 공백 비율**: {excessive_space_ratio}%
- **전체 문자 수**: {total_chars}
- **특이사항**: {special_blocks}

### 로컬 힌트 정보

다음은 PDF 구조 분석으로 감지된 패턴입니다. 변환 시 참고하세요:

{hint_json_pretty}

{chunk_text}

## 변환 규칙

### 1. 원문 우선
- 명백한 OCR 오류만 수정 (한자·영문 혼용, 맥락상 분명한 오류)
- 불확실하면 `[의심:추정값]` 형태로 표시
- 원본 형식(띄어쓰기, 줄바꿈)을 최대한 유지

### 2. 법률 용어 보정
- 법학 문맥에 맞게 교정 (예: "게약" → "계약")
- 사전에 없는 용어는 보정하지 말 것

### 3. 해설 처리
- 해설이 있으면 `explanation` 필드에 포함
- 해설이 없으면 빈 문자열 `""`

### 4. 선지 텍스트 정규화
- 각 선지의 `text` 필드에는 **해당 선지의 실제 내용**을 기입합니다.
- **`"동일"` 사용 조건 (매우 엄격하게 적용)**:
  - 모든 선지가 아주 짧은 키워드(예: "청약", "승낙", "계약") 또는 단어 수준이며,
  - 선지 간에 내용이 사실상 동일한 구조를 공유할 때만 `"동일"` 사용 가능.
- **`"동일"` 사용 금지 상황 (아래 중 하나라도 해당하면 반드시 전문 작성)**:
  - 각 선지가 완전한 문장·절·명제 형태인 경우
  - 각 선지가 서로 다른 독립적인 법적 사실이나 판례 내용을 서술하는 경우
  - 선지 내용이 10자를 넘는 경우
- 결론: **법학 객관식에서는 대부분의 경우 각 선지를 전문 작성**하는 것이 맞습니다.

### 5. 정오표 / 답 표기
- `correct` 필드: `true`(O) 또는 `false`(X)만 사용
- 다른 값(숫자, 문자) 금지

### 6. 불완전 문제 처리
텍스트 잘림, 페이지 경계 손실, 선지 누락 등으로 문제가 불완전한 경우 **해당 문제를 출력에서 제외**하세요.

불완전 판단 기준 (하나라도 해당하면 제외):
- 선택지(①~⑤ 또는 ㄱ~ㅁ)가 전혀 없거나 일부만 있어 정답을 특정할 수 없는 경우
- 문제 본문이 도중에 잘려 의미 파악이 불가능한 경우
- `[의심: 텍스트 잘림]` 등 잘림 표시가 있으며 핵심 내용이 누락된 경우

완전히 제외하며, 별도 플래그나 행을 남기지 않습니다.

### 7. ㄱㄴㄷ 조합선택형 문제 (중요)
문제 본문에 `ㄱ.`, `ㄴ.`, `ㄷ.`, `ㄹ.`, `ㅁ.` 형태의 하위 지문이 포함된 문제는 **ㄱㄴㄷ 조합선택형**입니다.

이 경우:
- `options[].num`: `"①"` 대신 `"ㄱ"`, `"ㄴ"`, `"ㄷ"`, `"ㄹ"`, `"ㅁ"` 사용
- `options[].text`: 각 지문(ㄱ/ㄴ/ㄷ)의 실제 내용
- `options[].correct`: 해당 지문이 옳으면 `true`, 옳지 않으면 `false`
- `options[].explanation`: 해당 지문에 대한 개별 해설
- `text` (문제 본문): ㄱ/ㄴ/ㄷ 하위 지문을 **제거**하고 질문 줄기(stem)만 포함
- `"동일"` 규칙 **적용 안 함** (모든 행에 각자 내용 작성)

**구분 방법**: ①②③④⑤ 선택지가 "ㄱ,ㄴ,ㄷ의 조합"(예: "ㄱ,ㄴ", "ㄴ,ㄷ,ㄹ")으로 이루어져 있으면 ㄱㄴㄷ형임.

## 출력 형식 (필수)

반드시 아래 JSON 형식으로 **JSON 외 다른 텍스트 없이** 응답하세요:

```json
{
  "questions": [
    {
      "id": 1,
      "text": "문제 내용 (첫 선지에만 전체 문제 텍스트)",
      "options": [
        {
          "num": "①",
          "text": "선지 내용",
          "correct": true,
          "explanation": "해설 내용"
        },
        {
          "num": "②",
          "text": "동일",
          "correct": false,
          "explanation": ""
        }
      ]
    },
    {
      "id": 2,
      "text": "다음 중 계약의 성립요건으로 옳지 않은 것은?",
      "options": [
        {
          "num": "①",
          "text": "청약",
          "correct": false,
          "explanation": "청약은 성립요건이 아님"
        }
      ]
    }
  ]
}
```

## 주의사항

1. **JSON 포맷 엄격함**: 따옴표, 쉼표, 괄호 완벽히 일치
2. **문자열 이스케이프**: JSON 내부 개행은 `\n`, 따옴표는 `\"` 처리
3. **배열 완전성**: 모든 문제에 대해 `id`, `text`, `options` 필수
4. **선지 필수**: 5개 중 1~4개만 있으면 안 됨 (명시된 개수 모두 포함)
5. **빈 값 규칙**: 해설 없음 → `""` (null 금지)
6. **중복 방지**: 같은 문제 ID나 선지가 2회 이상 나오면 안 됨
7. **JSON 외 텍스트 금지**: 설명, 인사말, 마크다운 펜스(`'''`) 불포함

## 템플릿 변수 설명

| 변수 | 예시 | 설명 |
|------|------|------|
| `{question_range}` | "1~8" | 청크 내 문제 번호 범위 |
| `{option_symbols}` | "circled" | 선지 기호 유형 (circled / korean / numeric) |
| `{options_per_question}` | 5 | 문제당 선지 수 |
| `{explanation_marker}` | "[해설]" | 해설 구분자 |
| `{broken_char_ratio}` | 2.3 | 깨진 문자 비율(%) |
| `{excessive_space_ratio}` | 5.1 | 공백 과다 비율(%) |
| `{total_chars}` | 3580 | 전체 문자 수 |
| `{special_blocks}` | "문3에 표 포함" | 특이 구조 |
| `{hint_json_pretty}` | (JSON 포맷) | 로컬 힌트 (구조화된 JSON) |
| `{chunk_text}` | (원본 텍스트) | 실제 변환할 텍스트 |
